# Implementation Plan: Unified Login with Role Portal

We will unify the login entry point at `http://localhost:3000/login` and introduce a **Role Portal** to handle multi-role users, resolving the infinite loop and permission confusion.

## 1. Create Role Portal Page (`apps/web/app/portal/page.tsx`)
- **Objective**: Create a landing page for users with multiple roles to select their desired workspace.
- **Features**:
  - Protected route (requires authentication).
  - Fetches user profile and roles from Supabase.
  - Displays selection cards for available roles (e.g., Super Admin, Landlord, Tenant).
  - **Links**:
    - **Super Admin**: External link to `http://localhost:3001/superadmin/dashboard`.
    - **Landlord/Tenant/Agent**: Internal links to their respective dashboards on Port 3000.

## 2. Update Login Logic (`apps/web/app/(auth)/login/page.tsx`)
- **Objective**: Stop automatic redirects for multi-role users.
- **Changes**:
  - Modify `onSubmit` success handler.
  - **Logic**:
    - If user has **> 1 role** (or specifically has `super_admin` + others) -> Redirect to `/portal`.
    - If user has **only 1 role** -> Auto-redirect to that specific dashboard.
  - Remove the strict "Force Super Admin to 3001" auto-redirect logic *at the login stage*, delegating it to the Portal.

## 3. Update Middleware (`apps/web/middleware.ts`)
- **Objective**: Allow Super Admins to stay on Port 3000 to view the Portal without being kicked out.
- **Changes**:
  - Exclude `/portal` from the "Super Admin must go to Port 3001" redirect rule.
  - Ensure `/portal` is protected (requires session).
