### 問題分析

您在 Supabase 中找不到 OpenAI API Key 的原因，通常有以下兩種可能：

1. **資料表尚未建立**：雖然程式碼中已經指定寫入 `ai_api_keys` 資料表，但該資料表的建立腳本（Migration SQL）尚未在您的 Supabase 資料庫中執行。
2. **資料加密**：即使找到了資料表，您也無法直接看到 `sk-proj-...` 開頭的明文，因為系統已強制執行「零明文儲存」策略。

***

### 解決方案：建立資料庫結構

請依照以下步驟，在 Supabase 的 SQL Editor 中執行建立資料表的指令。

#### 1. 找到資料表定義

資料表 `ai_api_keys` 的完整定義位於專案中的：
`supabase/migrations/20260213000000_create_ai_settings.sql`

#### 2. 執行 SQL 指令

請複製以下 SQL 程式碼，並在 Supabase Dashboard 的 **SQL Editor** 中執行，以建立必要的資料表結構：

```sql
-- 建立 ai_api_keys 資料表，用於儲存加密後的金鑰
CREATE TABLE IF NOT EXISTS public.ai_api_keys (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
    provider TEXT NOT NULL CHECK (provider IN (
        'openai', 'anthropic', 'gemini', 'deepseek', 'grok'
    )),
    api_key_encrypted TEXT NOT NULL, -- 這裡儲存密文
    iv TEXT NOT NULL,                -- 這裡儲存加密向量
    is_valid BOOLEAN DEFAULT NULL,
    last_validated_at TIMESTAMPTZ,
    is_active BOOLEAN NOT NULL DEFAULT true,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- 建立索引以優化查詢效能
CREATE INDEX idx_ai_api_keys_user_id ON public.ai_api_keys(user_id);
CREATE UNIQUE INDEX unique_active_ai_key_per_provider
    ON public.ai_api_keys(user_id, provider)
    WHERE (is_active = true);

-- 啟用 RLS (Row Level Security) 安全性政策
ALTER TABLE public.ai_api_keys ENABLE ROW LEVEL SECURITY;

-- 允許使用者管理自己的金鑰
CREATE POLICY "Superadmin can manage AI API keys"
    ON public.ai_api_keys FOR ALL
    USING (auth.uid() = user_id)
    WITH CHECK (auth.uid() = user_id);
```

### 關於「零明文儲存」的驗證

執行上述 SQL 後，當您在前端「AI 服務設定」頁面儲存金鑰時，Supabase 的 `ai_api_keys` 資料表中將會新增一筆記錄：

* **provider**: `openai`

* **api\_key\_encrypted**: 會是一串亂碼（例如 `U2FsdGVkX1...`），這就是加密後的密文。

* **iv**: 加密所需的初始化向量。

您將**不會**在資料庫的任何欄位中看到原始的 `sk-proj-...` 金鑰，這證明了「零明文儲存」機制正在正常運作。
