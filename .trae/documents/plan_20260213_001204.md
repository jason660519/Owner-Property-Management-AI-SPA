# Implementation Plan: Auto-fill Encrypted API Keys

I will implement the functionality to automatically retrieve, decrypt, and fill the API keys as requested. This involves changes to the backend API to return the encrypted data and the frontend to decrypt it using the shared key.

## 1. Backend API Modification
**File:** `apps/superadmin/app/api/ai-settings/keys/route.ts`
- Update the `GET` endpoint to include `api_key_encrypted` and `iv` fields in the Supabase query.
- This allows the frontend to receive the necessary data for decryption.

## 2. Frontend Logic Update
**File:** `apps/superadmin/lib/hooks/useAISettings.ts`
- Update the `SavedKey` interface to include an optional `decryptedKey` field.
- Modify the `fetchAll` function to:
  1. Receive the encrypted data.
  2. Iterate through each key.
  3. Use `decryptApiKey` (from `lib/crypto.ts`) to recover the plaintext key.
  4. Store the plaintext key in the state (only in memory).

## 3. UI Component Update
**File:** `apps/superadmin/components/ai-settings/ApiKeyManager.tsx`
- Update `ProviderKeyRow` component to:
  - Pre-fill the input field with `savedKey.decryptedKey` when the user clicks "Change" (更換).
  - (Optional) Add a toggle to reveal the full key in the view mode without entering edit mode, improving the UX.

## Security Note
This approach uses the `NEXT_PUBLIC_ENCRYPTION_KEY` which is accessible on the client side. This is acceptable for a Superadmin-only dashboard where convenience is prioritized, but it relies on the transport layer (HTTPS) and the assumption that the admin's browser is secure. The keys will be exposed to any script running on this page (XSS risk), which is a standard trade-off for "Show/Edit Key" functionality.
