# 實作剩餘角色儀表板與功能模組計畫

根據現有架構與需求，將依序完成 **Agent (房產經紀人)**、**Potential Buyer (潛在買家)** 與 **Service Provider (服務提供商)** 的儀表板開發。開發將遵循 Clean Architecture，使用 Server Actions 進行資料獲取，並結合現有的 `DashboardLayout` 與 `StatsGrid` 組件以確保一致性。

## 1. 核心架構與共用模組擴充
### 1.1 定義資料型別與介面
- 在 `apps/web/lib/actions/dashboard.ts` 中擴充以下介面：
  - `AgentDashboardStats`: 定義經紀人關注的指標 (如：活躍物件、待審核申請、預約看房數、本月佣金)。
  - `PotentialBuyerStats`: 定義潛在買家指標 (如：收藏物件、預約看房、出價狀態)。
  - `ServiceProviderStats`: 定義服務商指標 (如：待處理工單、本週行程、完工率)。

### 1.2 實作 Server Actions (Mock Data優先)
- 實作以下 Server Actions，初期使用 Mock Data 確保前端開發順暢與效能達標 (<200ms)，並預留 Supabase 整合點：
  - `getAgentDashboardStats()`
  - `getPotentialBuyerDashboardStats()`
  - `getServiceProviderDashboardStats()`

## 2. 角色儀表板實作 (依優先順序)

### 2.1 Agent Dashboard (房產經紀人)
**路徑**: `apps/web/app/(dashboard)/agent/dashboard/page.tsx`
- **KPI 指標**:
  - **活躍物件 (Active Listings)**: 管理中的上架物件數量。
  - **待處理申請 (Pending Applications)**: 需審核的租賃/買賣申請。
  - **即將到來的看房 (Upcoming Viewings)**: 今日/本週的預約。
  - **績效概覽**: 本月成交件數/預估佣金。
- **快速操作**: 新增物件、審核申請、行事曆檢視。

### 2.2 Potential Buyer Dashboard (潛在買家)
**路徑**: `apps/web/app/(dashboard)/buyer/potential/dashboard/page.tsx`
- **KPI 指標**:
  - **收藏物件 (Saved Properties)**: 關注列表中的物件數。
  - **看房行程 (Scheduled Viewings)**: 已預約的看房時間。
  - **出價狀態 (Active Offers)**: 已遞交的出價單狀態 (審核中/協商中)。
  - **新上架推薦 (New Matches)**: 符合偏好的新物件。
- **快速操作**: 搜尋物件、聯絡經紀人。

### 2.3 Service Provider Dashboard (服務提供商)
**路徑**: `apps/web/app/(dashboard)/service-provider/dashboard/page.tsx`
- **KPI 指標**:
  - **待處理工單 (Open Work Orders)**: 指派中且尚未完成的維修單。
  - **今日行程 (Today's Schedule)**: 需前往的維修地點與時間。
  - **本月收益 (Earnings)**: 已結案工單的預估收益。
  - **服務評分 (Rating)**: 用戶給予的平均評分。
- **快速操作**: 更新工單狀態、上傳維修照片。
