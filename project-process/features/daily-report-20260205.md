### 當日執行任務：聯繫頁面修復

#### 任務描述

診斷並修復 http://localhost:3000/contact 頁面提交失敗問題，確保資料庫寫入與郵件發送功能正常運作。

#### 執行細節

- 檢查前端表單提交邏輯與後端 API 路由 (`contact.ts`)。

- 創建 Supabase Migration (`20260205150000_create_contact_messages.sql`) 以建立 `contact_messages` 表。

- 實作資料庫插入邏輯與郵件發送的錯誤隔離機制。

- 加入 3 次重試機制以解決網路不穩導致的郵件發送失敗。

- 修正 Supabase 設定檔 (`config.toml`) 開放 SMTP 端口 54325。

- 撰寫並通過整合測試 (`contact.test.ts`)。

### 遇到的問題與解決方案

#### 問題 1：郵件服務連線被拒 (ECONNREFUSED)

Supabase 本地環境的 Mailpit 服務雖然運行，但 SMTP 端口 54325 預設被註解，導致後端無法連線。

解決方案：修改 supabase/config.toml，取消 smtp_port = 54325 的註解並重啟服務。

#### 問題 2：資料庫寫入失敗

對應的 contact_messages 表不存在。

解決方案：編寫 SQL Migration 檔案並執行遷移，同時配置 RLS 政策允許匿名插入。

### 工作心得與反思

本日的修復工作強調了「錯誤隔離」的重要性。在處理涉及多個外部依賴（如資料庫和郵件伺服器）的業務邏輯時，不應讓單一依賴的失敗阻斷整個流程。透過將資料庫寫入與郵件發送分離，並引入重試機制，我們顯著提升了系統的韌性。此外，完善的本地開發環境配置（如正確的端口映射）對於開發效率至關重要。
